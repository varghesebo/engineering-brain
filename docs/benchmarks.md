# Benchmarks and evaluation

Fixtures: synthetic small / medium / large TS+JS repositories, original and redistributable, generated by a script so measurements are reproducible. No customer code.

## Performance targets (proposed, to be validated, not claims)
| Metric | Target |
|---|---|
| New session initialization | < 1 s (excluding agent startup) |
| Retrieval | p95 < 500 ms on reference fixtures |
| Unchanged-repo reconciliation | < 5 s on reference fixtures |
| Indexing during editing | async, non-blocking |
| Context retrieval | default max 4,000 tokens, configurable |
| Idle | no CPU-intensive work |
| Languages | TypeScript, JavaScript; others via adapters |

## Quality metrics
Tokens before first meaningful edit · total tokens per task · **retrieval calls per task** · context precision/recall · missed dependencies · stale/incorrect retrieval rate · initial and incremental index time · CPU/RAM/disk · (v0.3) test-selection accuracy and escaped regressions.

## Method
Scripted task set on fixtures; baseline Claude Code / Codex without the tool vs with it, same tasks, repeated runs; record tokens, calls, edit correctness. Ground truth dependencies come from fixture generation. A component that does not show measurable value is cut before expanding scope. The tool must prove savings **without** introducing incorrect code relationships.
