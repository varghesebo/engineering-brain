# Acceptance specifications (v0.1)

Executable specs. Each test: **Fixture / Procedure / Expected / Pass threshold / Failure behaviour**. All fixtures are synthetic, generated by a committed script with a fixed seed (`tests/fixtures/gen`), and listed with their SHA-256 in a manifest. Sizes: S=100, M=2,000, L=20,000 TS files (generator proven in spike S2/S3). Platforms: tests run per OS (macOS, Linux, Windows); a test not supported on an OS is reported **skipped with a reason**, never silently passed. v0.1 is production-ready only with a report where every test is pass or explicitly skipped-with-reason and the benchmark section is filled.

## Benchmarks required in the report (targets are proposals, not claims)
Index time S/M/L (initial, 1% incremental, unchanged); unchanged reconcile < 5 s (L); retrieval p95 < 500 ms (M, 1000 queries); session init < 1 s; RSS/CPU/disk; hash-verified freshness time (L, warm and **cold** cache); heuristic freshness time (L); default context ≤ 4,000 tokens; token savings vs baseline agent runs (tokens to first edit, total, **retrieval calls**, missed dependencies).

## Report format
`acceptance-report.md` generated by CI per OS: test id, result (pass/fail/skipped+reason), measured values, fixture manifest hash, tool versions, commit SHA. Unverified items are listed explicitly.
