# Sentinel 3B report: verification campaigns and test evidence (non-executing portion)

Status: **PARTIAL, review-limited.** The deterministic ingestion, campaign, invalidation, traceability and explanation layers are implemented and tested. The pack's first deliverable, a sandboxed `verification-worker` that RUNS repository tests, is deliberately NOT enabled: `sentinel verify <id> --run` fails closed because this machine cannot verify network-egress denial or CPU/memory/process limits (only macOS `sandbox-exec` file-write denial is probed). Results are recorded from signed or accepted CI evidence imports instead. Independent review is a fresh Claude agent (NOT Codex); see the review section.

## Built
- Adapters (`evidence/importers.ts`): `vitest` (jest-compatible JSON), `pytest` (`--junitxml`), `playwright` (JSON reporter; a flaky pass is recorded as failed, interrupted runs are partial), plus the H4 JUnit/LCOV/Cobertura/SARIF/jest parsers.
- Schema v9 (`sentinel_trace`); outcomes extended to `not_run` and `invalidated`; evidence-import formats extended (edited v7/v8 CHECKs in place; they were unpublished, but a store already at v7/v8 would not gain the new values: see limits).
- `sentinel/campaigns.ts`: three passes (FUNCTIONAL, ADVERSARIAL, SYSTEM_ASSURANCE) with NOT_RUN/NOT_REQUIRED/PASSED/FAILED/INCOMPLETE/INVALIDATED; `outcomeOfCounts` (failed, errored, timed-out, partial, all-skipped, skipped, empty all non-green); `recordFromImport` (signed/accepted, complete, still-applying imports only, and only for the exact current revision on a clean tree); `invalidateEvidence` (explicit append-only `invalidated` records on source, policy or environment change); requirement -> behavior -> test -> evidence traceability with honest missing-coverage; `planVerification` (campaigns, test selection with proof and unknown areas, policy sampling A1 0 / A2 5 / A3 20 / A4 50, enforcement assessment, explanation); `refuseRunIfUnenforceable`.
- CLI: `sentinel verify <id> --dry-run|--explain|--run`, `sentinel import <id> --check-id <c> --import <evidence import id>`, `sentinel trace [add] <id>`. `--run` is rejected for every command except `sentinel`. No `run_shell` MCP tool exists.

## Verification (run, Node 22.23.3, macOS)
Typecheck clean; full suite **44 files, 557 tests passed, 0 failed** (after the review fixes below) (`evidence/s3b-vitest-verbose.txt`). An earlier run had 1 failure (the Foundation test that no command accepts `--run`); fixed by rejecting `--run` outside `sentinel`, then the suite was re-run.
Covers: failing/timed-out/skipped/empty results never satisfy a mandatory check; empty pass is NOT_RUN and one passing pass does not make others pass; environment change makes evidence stale and invalidated records are appended; quarantined, forged (signature over different bytes) and wrong-revision artifacts cannot back a check; code changed after the run is refused; Playwright/vitest/pytest parsing incl. malformed and DOCTYPE input; traceability marks a link to a test absent from the evidence as unverified; selection explanation and policy sample keeping a hidden dynamic dependency; `--run` refused (also unauthenticated), dry run/explain/trace available; parallel workers never take the same queued item and an interrupted worker's items are re-queued after its lease expires.

## Limits and not done
- No test execution (see above). Enforcement requires file-write confinement, network denial verified by a probe, and CPU/memory/process limits; the last two are not available, so `--run` can never be permitted on this build.
- Not implemented: Jest/pytest/Playwright subprocess adapters that execute and record commands/versions/seeds/output hashes; build-dependency invalidation beyond the whole-source fingerprint; replay/checksum of downloaded CI artifacts beyond the H4 signature policy; mutation/fuzz/property adapters; requirement links are entered manually (nothing infers them).
- Stores already at schema v7/v8 would not gain the extended CHECK values (the edits were made in place to unpublished migrations).
- Single-machine: Linux, Windows, Node 24 untested. All 3A limits apply (same-user key file, no identity mapping, committed-changes-only scope check).

## Independent review (fresh read-only Claude agent; NOT Codex, not a strict audit)
12 confirmed findings; fixed with regression tests: import not tied to the check it backs (now a per-check format map, one artifact backs one check, scope/build/review checks never import-backed); `scope` forgeable through import; traceability reading "verified" for a non-passing check; recorded evidence not re-validated against its import (now stale when the import is rejected or stops applying); environment invalidation not wired into gating (now compared with the store's current environment assumptions); selected tests not required in the run (now `incomplete`); Playwright/jest report-level errors and total mismatches (now partial); JUnit skip hiding a failure; dry-run wording; SARIF dead end (SARIF now backs lint/typecheck); migration edited in place (stores from earlier dev builds are now refused with a clear message; that refusal path is untested).
Deliberate choices: an operator-ACCEPTED artifact may back a check (a human decision; an invalid-signature artifact can never be accepted). Still open: SARIF with zero findings counts as passed; pytest rows without a `file` attribute cannot be traced; post-fix state not re-reviewed; no subprocess adapters, so nothing is executed.
